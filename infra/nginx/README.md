# Публикация демо-стенда на `braining.space`

Конфигурация nginx **хоста** (не того, что внутри контейнера `web`). Здесь она
лежит копией: файл, который реально работает, находится в
`/etc/nginx/sites-available/cosmo-track.conf`, и правки нужно вносить в оба места.

## Что стоит за доменом

```
браузер ──TLS──► nginx хоста :443 ──http──► контейнер web :8080 ──► api :8000
                 (cosmo-track.conf)          (apps/web/nginx.conf)     (FastAPI)
```

Хостовый nginx только терминирует TLS и проксирует всё на `127.0.0.1:8080`.
Разбор путей — статика, `/api/`, `/tiles/` — целиком внутри контейнера, поэтому
конфигурация стенда переносится на другой домен без правок этого файла.

Сертификат — существующий wildcard Let's Encrypt `*.braining.space`, выпущенный
для соседнего проекта. Свой мы не выпускали: домен тот же, продлевает его тот же
certbot, и вмешательство в его расписание сломало бы и поддомены.

## Домен был занят другим проектом

До 2026-09-05 на `braining.space` работало приложение Braining (SPA из
`/var/www/braining.space` плюс backend на `127.0.0.1:8001`). Его конфигурация
**закомментирована целиком**, а не удалена:

- `/etc/nginx/sites-available/braining.space.conf` — закомментированная версия
  с инструкцией по возврату в шапке;
- `/etc/nginx/sites-available/braining.space.conf.bak-<дата>` — нетронутый оригинал.

Сам backend Braining на `127.0.0.1:8001` продолжает работать — снаружи по этому
домену он просто больше не виден.

Поддомены `id.braining.space` и `tg.braining.space` обслуживаются отдельными
конфигами и не затрагивались.

## Вернуть Braining обратно

```bash
rm /etc/nginx/sites-enabled/cosmo-track.conf
cp /etc/nginx/sites-available/braining.space.conf.bak-<дата> \
   /etc/nginx/sites-available/braining.space.conf
nginx -t && systemctl reload nginx
```

## Проверка после изменений

```bash
nginx -t                                   # конфигурация валидна
systemctl reload nginx                     # применить без разрыва соединений
curl -sI https://braining.space/           # 200 и наш заголовок
curl -s https://braining.space/health/ready
```

## Что учесть перед сдачей

- Стенд доступен из интернета **без аутентификации**: любой, кто знает адрес,
  может создать полигон и запустить анализ, а анализ — это работа CatBoost на
  процессоре. Для демо это принятое решение; после показа стенд стоит погасить
  (`docker compose stop web api`) или вернуть домен прежнему проекту.
- Порты `8000` и `8080` контейнеров опубликованы на `0.0.0.0`, то есть доступны
  и напрямую, в обход TLS. Домен ходит через 443, но прямой доступ по IP остаётся.
- База на `127.0.0.1:55432` наружу не смотрит — так и должно остаться.
